# Epic 07 Learnings -- Advanced Stochastic Modeling

## Patterns Established

- **VARSeasonParameters nested struct**: Season-level grouping of coefficient matrices and scales extracted into a dedicated struct (`VARSeasonParameters` in `src/StochasticProcess/vectorautoregressive.jl`). This avoids passing separate coefficient and scale dicts around and mirrors the `UnivariateAutoRegressive` nested-type pattern in `autoregressive.jl`.
- **Reused noise model construction**: `__build_var_noise_naive_dict` transforms the VAR params dict into Naive-compatible format (stripping `coefficient_matrices`, renaming `models` -> `distributions`, adding `kind: "Gaussian"`) and passes it to `Naive(dict, e)`. This avoids duplicating noise model parsing logic (`src/StochasticProcess/vectorautoregressive.jl` lines 108-127).
- **Flat STCHP indexing for VAR**: VAR(p) with N elements uses index offset `(n-1) * max_lag + 1` for element `n`, giving a flat array of `N * max_lag` state variables. Memory shift constraints span indices that are NOT in the `index_t` set (`src/Engines/sddp/build.jl` lines 562-692).
- **Abstract sentinel type pattern for optional components**: `AbstractMarkovChain` / `NoMarkovChain` / `MarkovChainConfig` follows the established pattern from `InflowNonNegativity`. Multiple dispatch on `has_markov_chain(::AbstractMarkovChain)` replaces `if/else` chains throughout the build pipeline (`src/Scenarios/markov.jl`).
- **Multi-process `InflowScenarios`**: `stochastic_process` field changed from `AbstractStochasticProcess` to `Dict{Int, AbstractStochasticProcess}`. Legacy single-process JSONs are wrapped in `Dict(1 => process)` automatically. Markov JSONs use string-integer keys parsed to `Int` (`src/Scenarios/inflow-validators.jl` lines 92-163).
- **Node type extraction helpers**: `__extract_stage` and `__extract_markov_state` are overloaded for `Integer` (legacy) and `Tuple{Int,Int}` (Markov) node types. All subproblem builder and validation code calls these instead of raw indexing (`src/Engines/sddp/build.jl` lines 803-825).
- **Stage datetime map**: Added `stage_datetimes` (keyed by `n.stage`) alongside the existing `node_datetimes` (keyed by `n.id`) inside `__generate_subproblem_builder`. Markov mode uses `stage_datetimes[stage]`; legacy uses `node_datetimes[node]` (`src/Engines/sddp/build.jl` lines 840-849).
- **Per-Markov-state SAA generation with prime offset**: `generate_saa(scenarios, num_stages, seed)` generates one SAA per Markov state using `seed + (state - 1) * 7919` (prime multiplier for independence). Returns `Dict{Int, Vector{...}}` keyed by Markov state (`src/Engines/sddp/build.jl` lines 703-725).
- **`OutOfSampleMonteCarlo` with `use_insample_transition=true`**: Validation reuses the in-sample graph transitions but replaces noise terms. The sampler lambda extracts stage and Markov state from the node and looks up the pre-generated out-of-sample SAA (`src/Engines/sddp/validate.jl` lines 83-94).
- **Standalone statistics computation**: `_compute_validation_statistics` uses Julia stdlib `Statistics.mean/std/quantile` without adding new package dependencies. Small-sample CI uses an inline lookup table `_t_quantile_95(df)` rather than importing `Distributions.jl` (`src/Engines/sddp/validate.jl` lines 136-200).
- **Validation output with `validation_` prefix**: `__write_validation_simulation_results` mirrors `__write_simulation_results` but prefixes output keys with `validation_`. Written to the same directory via `cd(path)` pattern (`src/Engines/sddp/validate.jl` lines 225-336).
- **`__is_multi_process_dict` detection**: Distinguishes Markov format (no "kind"/"params" keys) from legacy format at parse time without requiring a separate config key (`src/Scenarios/inflow-validators.jl` lines 92-94).

## Architectural Decisions

- **`Union{OutOfSampleValidation, Nothing}` for validation field on `SDDPEngine`**: The plan proposed an abstract type hierarchy (`NoValidation`/`OutOfSampleValidation`) for consistency. The implementation used `Union{T, Nothing}` because validation has no meaningful empty-default behavior -- it either exists or the caller should error. This is the one case in the codebase where `Union{T, Nothing}` is used for an engine field. The `get_validation_definition` accessor returns `nothing` when absent; the study-level `validate` function checks `isnothing` and errors immediately (`src/Engines/Engines.jl` line 233, `src/study.jl` line 90).
- **Transition matrix in-place conversion**: `__validate_transition_matrices!` converts JSON `Vector{Any}` to `Vector{Matrix{Float64}}` **and writes back** into `d["transition_matrices"]` before construction. This avoids a second parsing pass but requires callers to understand the dict is mutated during validation (`src/Scenarios/markov-validators.jl` lines 153-157).
- **Markov graph bypasses SDDPlab's `Graph` entirely**: When Markov is active, `__build_graph` calls `SDDP.MarkovianGraph(mc.transition_matrices)` directly and ignores the `scenarios.graph` field. Stage count comes from `scenarios.graph.nodes` for load/datetime lookups but the SDDP graph structure is fully determined by transition matrices (`src/Engines/sddp/build.jl` lines 776-778).
- **OOS SAA always truncated to non-negative**: The out-of-sample SAA in `Lab.validate` always applies `max.(0.0, omega)` regardless of the `InflowNonNegativity` method. The design note acknowledges this is a safe approximation because the validate signature does not receive the engine (`src/Engines/sddp/validate.jl` lines 50-74). Future work: pass the inflow method through to validate.
- **Coefficient matrices in normalized space**: VAR recurrence constraints operate on `(X - mu) / sigma` space with matrix `Phi` applied to normalized lagged values. This matches the AR normalization convention. The matrix is NOT in raw units, meaning `Phi[n,m] = 0.5` means 50% of one standard deviation of hydro m drives hydro n's normalized residual (`src/Engines/sddp/build.jl` lines 619-633).

## Conventions Adopted

- **VAR STCHP flat indexing**: `index_t[n] = (n-1) * max_lag + 1` for element `n` in a VAR model. Memory shift states are all indices not in `index_t`. This is consistent with the AR model which uses variable per-element lag counts; VAR simplifies it since all elements share `max_lag`.
- **Prime offset for per-state seeds**: `seed + (state - 1) * 7919` ensures Markov-state SAAs are independently seeded. The prime 7919 is large enough to avoid overlap for any realistic number of states (< 1000).
- **Contiguous-lags requirement**: VAR `coefficient_matrices` must provide all lags `1..max_lag` for every season (no gaps). Validated in `__validate_vectorautoregressive_consistency!`. This simplifies indexing by avoiding variable-lag-count structures.
- **String-integer keys for Markov process JSON**: The Markov inflow format uses string keys `"1"`, `"2"`, ... (JSON only allows string keys). These are parsed to `Int` via `tryparse`. Non-parseable keys produce a clear `AssertionError` (`src/Scenarios/inflow-validators.jl` lines 132-138).
- **`SDDP.add_all_cuts` before OOS simulation**: `Lab.validate` calls `SDDP.add_all_cuts(model.policy_graph)` wrapped in a try/catch before constructing the `OutOfSampleMonteCarlo` sampler. This ensures all cuts from training are available for the simulation (`src/Engines/sddp/validate.jl` lines 77-81).
- **`stage_to_node_id` map for load lookup**: Markov mode needs to look up load data by the `node_id` used in the `ScenariosData.graph`, but the SDDP graph only provides a stage index. A `stage_to_node_id` map is precomputed in `__generate_subproblem_builder` and used for `get_load` calls (`src/Engines/sddp/build.jl` lines 848-850).

## Surprises & Deviations

- **`Union{T, Nothing}` chosen over abstract type for validation**: The ticket implementation guide offered both options and recommended the abstract type pattern for consistency. The implementation chose `Union{OutOfSampleValidation, Nothing}` because validation is qualitatively different from system entities -- its absence should error, not silently no-op. This is documented in the design note in `src/Engines/Engines.jl` line 233.
- **OOS SAA truncation simplification**: The plan specified that out-of-sample SAA should apply the same truncation as training (conditional on `InflowNonNegativity` method). The implementation always truncates to non-negative. This is physically safe but slightly over-constrains scenarios for `InflowNone`/`InflowPenalty` methods where the AR model can produce negative noise terms that the model handles internally. The comment in `src/Engines/sddp/validate.jl` lines 48-74 acknowledges this and flags it for future refinement.
- **`generate_saa/4` signature added to `validate.jl`**: The plan placed out-of-sample SAA generation logic inside `Lab.validate`. A separate `generate_saa(scenarios, num_stages, seed, branchings)` overload was added in `validate.jl` (rather than the main build module) to keep validation concerns isolated. This function duplicates the structure of `generate_saa/2` in `build.jl` (`src/Engines/sddp/validate.jl` lines 1-21).
- **No changes to `StochasticProcess.jl` module exports for VAR**: The ticket specified adding `VectorAutoRegressive` to exports. The `__kind_factory!` mechanism resolves type names by looking up `getfield(Module, Symbol(kind))`, so the type only needs to exist in the module -- it does NOT need to be exported for JSON construction to work. The export was still added for API completeness.

## Recommendations for Future Epics

- **Pass `InflowNonNegativity` through `Lab.validate`**: The current implementation always truncates OOS SAA. Epic 08 or 09 should extend the `Lab.validate` signature (or the `OutOfSampleValidation` struct) to include the inflow method so truncation matches training exactly. See `src/Engines/sddp/validate.jl` lines 48-74 for the design note.
- **Validation output mirrors simulation output exactly**: `__write_validation_simulation_results` in `validate.jl` maintains a separate copy of the `map_variable_output` and `map_variable_entities` dicts from `save_simulation.jl`. If new entity types are added in future epics, both locations must be updated. Consider extracting these maps to a shared function.
- **Abstract type pattern is the default; document the `Union` exception**: Future engineers should use `NoX`/`X` sentinel hierarchy unless there is an explicit reason for `Union{T, Nothing}`. The validation field is the sole documented exception (`src/Engines/Engines.jl` line 233).
- **Markov chain test case**: The existing test suite exercises Markov with `AutoRegressive` processes. Testing with `VectorAutoRegressive` + Markov combination (per ticket-032 acceptance criterion) should be verified end-to-end in a future test epic.
- **`__add_load_balance!` parameter count**: As of Epic 07 the function has 14 parameters. The epic-06 learnings set a refactor threshold at 15+. This limit has not yet been crossed but should be addressed before adding more entity types.
